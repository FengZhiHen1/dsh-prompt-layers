# 提示词层机制

## 文件和激活

全局、供应商、模型 YAML 由目录枚举，文件名不参与匹配。yaml parser 拒绝重复键、alias、显式 tag、merge 和非字符串键，再以发布 Schema 校验；文件适配器解析所有 contentFile，保留来源路径并冻结正文。

单文件上限 1 MiB、完整候选上限 4 MiB、最多 256 文件；UI 写队列有界。文件路径只允许受控相对 YAML 路径和 content/ 下 Markdown，拒绝符号链接与非法 UTF8。全量读取后重新枚举并校验内容/文件指纹，变化则拒绝该候选。

轮询默认每秒一次，覆盖 Windows 原子替换场景；generated 不参与候选哈希。无变化不重新激活。每次成功候选完整替换不可变内存快照；失败保留整套旧快照，首次失败原生回退；插件卸载清空快照。

## 合成

内核支持 global → provider → 精确 provider/model 三层。自定义 ID 以 custom: 开头，初次定义必须有非空正文（禁用也必须）；上层只覆写显式字段。正文来源整体替换，不拼接；when 整体继承或替换，不对子字段做并集。

排序基线为原生顺序、全局首次定义、供应商首次定义、模型首次定义。position: default 恢复首次定义槽位。显式 before/after 从基线摘出节点挂到锚点，按基线键稳定展开 before→anchor→after。自锚、循环、缺失、禁用或不能证明的条件锚点拒绝。

Agent 身份取真实 composedPreset 和委派事实；不存在身份时显式条件不匹配。PowerShell 条件按该 Agent 可见的 `pwsh` 工具判定；该工具不可见时不匹配，其他自定义 shell 后端不在判定范围内。

现行适配器按 Agent 在 `systemPrompt.assemble` 上下文里声明的 `provider`/`model` 激活 provider/model 层；它们与宿主 `{{provider}}`/`{{model}}` 变量同源。`agent/request` 的请求级路由覆盖发生在组装之后，不会重建已渲染提示词，因此模型层不跟随该覆盖；这是已知边界，不是按显示名或旧模型猜测。

## 宿主边界和观察

waterfall 调用 next() 后只替换 sections，保留 contexts/tools/variables。既有段均保守标为受管；修改必须明确 allowManagedOverride。不会读取宿主私有 registry、修改完整提示词或重写工具。

装配观察只记录 ID、层来源、锚点、预计顺序和快照版本；预览不等于请求使用。系统消息提交后可比较预期哈希，区分 committed 与 suppressed-or-changed，不持久化正文。complete 在 waterfall 后强制恢复，多个 complete 仍走宿主原生失败。

结构诊断最多保留 32 条观察与 64 组 scope 目录；状态与索引写到 generated，只是可重建输出。状态不包含绝对私有路径或完整请求。

## 编辑与导入

UI 把全部草稿合并成一次 `commit`：载入一次快照、校验整套候选 revision，在同一份 YAML 文档 AST 上依次应用 save/remove，最后只写一次文件；过期或非法时整批拒绝并保留草稿。导入先预检所有冲突，再写正文，最后写引用 YAML。导入结果是普通 Section，不增加模板专用运行时。重复 ID、本地正文差异不自动合并，插件升级不回写。

多文件编辑没有事务协议：两次合法写入之间可能短暂激活中间合法版本。每次候选内部一致不等于跨多次编辑事务。权限由宿主与 OS 承担，插件不新增批准队列。
