# DSR-008：模型层按装配实际渲染的路由激活

> 状态：**已落地（源码与静态闸）**，2026-10-28；实例级真实请求复验待用户重启后执行。取代 `DSR-007` 中“读 `agent.options` 即得声明路由”的部分，工具能力判定不变。

## 背景

`DSR-007` 的前提是：宿主 `system-prompt/assemble` 时 `agent.options.provider/model` 与原生 `{{provider}}`/`{{model}}` 变量同源，因此模型层可直接用它做精确匹配。2026-10-28 在稳定实例上核对两条真实会话的初始系统提示词时发现该前提不成立：**模型层命中的路由与提示词身份行、真实请求都不一致**。

现场（同一份配置 `global.yaml` + `models/{sol-main-delegation,weak-deepseek-v4.1-flash,weak-glm-5.3-flash,weak-gpt-6-luna}.yaml`）：

| 会话 | 会话模型选择（`model/selection` 与请求头） | 提示词身份行 | `custom:` 段实际命中 |
| --- | --- | --- | --- |
| `5dc26d9f`（`cloud/group/gpt-6.1-sol`） | sol | sol | 三条弱模型段，**无** `custom:sol-main-delegation` |
| `ee31ead3`（`cloud/group/deepseek-v4.1-flash`） | flash | flash | **`custom:sol-main-delegation`**，无弱模型段 |
| 子智能体 `0e04f3d9` / `f4274b16` | sol（继承父级请求头） | sol | 无模型段（`when.agent.role: main` 排除，符合预期） |

前两行为镜像错配，且逐段正文与 `content/*.md` 逐字比对确认，不是导入或配置问题（`status.json` 为 `active`，`sections-index.json` 各 `custom:` 条目 `matched: true`）。

## 事实（0.2.1-rc.2 源码）

- `@deepseek-ai/dsh-api-session-controller` 的 `createAgent()` 一律用 `agentOptions() = ctx.agentDefaultModel.currentSelection()` 填 `agent.options` —— 这是 **profile 里的“应用默认模型”**，不是会话模型。
- 同一控制器的 `selectModel()`（界面换模型）在 `selectForNextRequest()` 之后还调用 `agentDefaultModel.saveSelection(selected)`，**任一会话换模型都会改写该默认值**，因此 `agent.options` 与某条会话的真实路由可相差一到两次切换。
- 会话真实路由由 `selectionFor()` 决定（待生效选择 > 最近 `request/header` > 默认模型），并由 `@deepseek-ai/dsh-agent` 的 `installModelSelection()` 在同一 `system-prompt/assemble` waterfall 内、`next()` 之后覆写 `assembly.variables.provider/model`；`agent/request` 也用这条选择。
- `prompt-layers` 以 `{ prepend: true }` 注册该 waterfall，是链上最外层：它的 `next()` 返回时读到的 `assembly.variables` 已经是覆写后的会话路由。

## 决策

1. `assemblyFacts(ctx, context, assembly)` 增加第三个参数；路由读 `assembly.variables.provider/model`，两者都是非空字符串时采用。
2. 装配未声明路由（无 agent、变量缺失、非 API 会话等）时回退 `agent.options.provider/model`，保持既有路径行为。
3. `status.modelLayers` 的取值沿用历史名 `declared-route`，语义即“该次装配实际渲染的路由”，避免状态字段跨版本改名。
4. `agent/request` 请求级覆盖仍不重建已渲染提示词：该边界不变，验收必须单列。
5. 文档、`client.js` 文案与决策记录同步改写：`agent.options` 只是创建时快照，不能作为路由来源。

## 后果与限制

- 同一实例里不同会话可以各自命中不同模型层，不再被全局默认模型染色；子智能体的 `role` 条件语义不变。
- 仍无法跟随 `agent/request` 的晚路由覆盖；若宿主未来提供组装后重组接口，需重新验证晚改路由、重试与压缩恢复。
- 仍未验证（需重启实例）：真实请求注入、模型切换后提示词段是否随选择切换、模型行为 A/B。

## 验证

- 单测：`test/runtime-v1.test.mjs` 新增「the assembly route wins over the creation-time Agent options」，用真实 `system-prompt/assemble` waterfall 覆写变量，证明 `agent.options` 指向 `model-y` 时命中的是 `model-x` 的模型层；原有「provider and model candidates activate on the declared route only」继续覆盖无路由变量时的回退路径。
- 静态闸：`pnpm check`（`node --check` + `node --test`）与仓库分层门禁。
