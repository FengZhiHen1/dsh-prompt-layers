# DSR-007：按声明路由激活模型层与工具能力判定

> 2026-10-28：本记录的事实 1、2 关于“`agent.options` 与原生 `{{provider}}`/`{{model}}` 同源”的前提在 0.2.1-rc.2 上实测不成立，路由来源与激活口径已由 `DSR-008` 取代；工具能力判定与 PowerShell 锚点结论仍然有效。

2026-10-17：用户在 test 模板配置讨论中指出现有检查过保守，要求模型级执行纪律能真正匹配资源受限模型、PowerShell 指引能在本机 PowerShell 环境导入。主 Agent 统筹先改为 global，随后按用户修正改为只对弱模型使用。此前 `DSR-006` 的“阻断 provider/model 候选激活”结论由本决策取代。

## 事实

- DSH 0.2.1-rc.2 的 `assembleContextFor` 把当前 agent 作为 `assemble` 上下文传入；agent-loop 自身的 `{{provider}}`/`{{model}}` 变量取 `agent.options.provider/model`。模型层与原生变量可以在同一时点拿到声明路由。
- `agent/request` 与 `prepareCall` 在系统提示词渲染之后；已渲染文本不会因请求级路由覆盖或 retry 重建。该覆盖不等同于声明路由，插件无法在组装时观察。
- `tools.get('pwsh', agent)` 的 scoped 视图能证明该 Agent 可见底层 pwsh 工具；工具存在即证明可执行 PowerShell。未暴露该工具的自定义 shell 后端不匹配。
- `tool:pwsh` 是条件原生段：有该工具的 preset 的 assembly 才有它，没有的 preset 没有。`validateHost` 不能用固定的 `powershell: false/true` 叉乘每个 preset，否则会给无该工具的 preset 伪造一个不存在的锚点。

## 决策

1. `assemblyFacts` 增加 `provider`/`model`，取 `agent.options`；与宿主原生变量同源，不读取显示名、旧模型或私有字段。
2. 移除 `runtime.activate` 对含 provider/model 候选的硬阻断；`status.modelLayers` 记为 `declared-route`，workspace 的 `capabilities.modelLayers` 为 true。
3. PowerShell 条件按 `ctx.tools.get('pwsh', agent) !== undefined` 判定；workspace 的能力字段返回 `available`/`unavailable`，不再把存在工具判为 unknown。
4. `flash-main-coordination` 的推荐作用域改为 model，保留 `when.agent.role: main`；只在弱模型范围内对主 Agent 生效。共享执行核心仍推荐精确 model。
5. Host 的 `validateHost` 对每个已配置 provider/model target 做合成校验，不只校验 global/preset；PowerShell 能力从该次 assembly 的原生 `tool:pwsh` 推导，不再对每个 preset 叉乘 `powershell: false/true`。
6. `templates/catalog.json` 的 `pwsh-guidance` 默认 `position: after: tool:pwsh`；模板加入草稿与 Host import 都落盘该位置。这是布局默认值，不是条件；没有 `tool:pwsh` 的 Agent 仍按 `when` 不匹配。

## 边界

- 模型层跟随声明路由；请求级 `agent/request` 覆盖不保证。该限制写入 README、技术栈设计、需求与部署记录，真实验收必须单列，不把配置激活写成最终请求已覆盖。
- 不按 OS 名、工具显示名或旧模型推断路由或方言；不引入私有字段、函数劫持、user-role 补丁或默认路由钉死。
- PowerShell 只认 `pwsh` 工具身份；自定义后端若实际使用 PowerShell 但不暴露该工具，需要后端补齐身份。
- `templates/*.md` 正文不变；主统筹仅改推荐元数据，已导入正文不自动迁移。PowerShell 模板只改 catalog 的默认 `position`，正文不变。
- `after: tool:pwsh` 依赖原生工具段；目标 Agent 没有 `pwsh` 时条件不匹配，锚点不参与，不能把该位置当作跨宿主固定顺序。
- 真实请求注入、请求级覆盖、停用重启用和模型行为 A/B 仍需独立证据；代码测试只证明当前契约。
