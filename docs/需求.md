# dsh-prompt-layers 需求

目标是让用户按全局、供应商及精确模型管理系统提示词 Section，并以 Agent 身份和可信工具能力限定适用范围。Agent 与 Web UI 编辑同一份 YAML/Markdown，模板必须显式导入。

| ID | 要求 | 验收 |
| --- | --- | --- |
| PL-01 | 三层精确匹配，按字段继承，同 ID 正文整体替换 | G/P/M、跨 provider 同名模型、禁用恢复 |
| PL-02 | 新增、修改、禁用与定位自定义及可操作既有 Section | default 恢复首次槽位；严格锚点与环拒绝 |
| PL-03 | 严格解析、安全文件引用与完整候选校验 | 重复键、alias/tag/merge、非法UTF8、越界拒绝 |
| PL-04 | 全量激活、内存最后有效快照、重启原生回退 | 任意文件损坏不会部分更新 |
| PL-05 | 主/子 Agent、preset 精确条件；Agent 可见的 pwsh 工具匹配 | 未注册不猜测；不沿用父模型 |
| PL-06 | Web UI 与 Agent 同源编辑、乐观修订冲突拒绝 | 不静默覆盖外部修改；保留草稿 |
| PL-07 | 七份批准模板版本化显式导入，两条装配入口 | 不安装即注入；复制任务只复制 |
| PL-08 | 区分保存、激活、预览与请求实际使用 | 只存结构诊断，complete/下游改写不能假成功 |
| PL-09 | 与 Guardrails 完全独立 | 不调用、不依赖、不把拒绝记录当匹配依据 |
| PL-10 | 全部副作用随插件卸载回收 | 定时观察、事件、UI、API解除 |

不增加 Agent 常驻工具、专用 CLI、权限系统、秘密库、远程同步或持久化请求正文。不修改动态用户上下文、工具 Schema 或权限，不绕过 complete。

模型层按该次装配实际渲染的 provider/model 应用：路由取宿主 assembly 的 `provider`/`model` 变量（Session 模型选择在装配 waterfall 内覆写），装配未声明路由时才回退 Agent 创建选项；不能用显示名、旧模型或 `agent.options` 里的默认模型快照猜测。宿主在组装之后还有 `agent/request` 请求级路由环节，若该环节覆盖声明模型，已渲染提示词不会重建；这一边界、失败表现和真实请求证据必须单列，不能把配置激活写成最终路由已覆盖。完整 V1 验收仍要求真实目标版本请求与浏览器证据；代码测试不替代这些证据。
